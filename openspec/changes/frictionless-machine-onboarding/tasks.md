## 2. Device authorization backend routes

- [x] 2.1 Add `POST/GET /device/authorize` (Access-protected, identity-authed) in `backend/src/index.ts`: resolve the caller's account, take the requested `label` + loopback `cb` + `state`, and render the approval surface (delegated to UI).
- [x] 2.2 On approval, resolve-or-create the Machine, detect an active recently-seen conflict, and (per the chosen replace/separate outcome) issue the key; store a **short-lived, single-use authorization code → (account, machine_id, key)** in the strongly consistent registry (D1), with `expires_at`. Conflict detection and the replace/separate decision are keyed by the exact `machine_id` shown on the approval page (threaded through a hidden form field), not re-resolved by label on submit — a caught-in-manual-testing bug had `replace` retarget the wrong machine when a concurrent `separate` added a second same-labeled row between GET and POST.
- [x] 2.3 Redirect to the loopback `cb` with the one-time `code` and echoed `state` (never the key).
- [x] 2.4 Add `POST /device/token` (Access-bypass path) that exchanges a valid, unexpired, unredeemed code for the access key as JSON; mark the code redeemed (single-use); reject unknown/expired/replayed codes.
- [x] 2.5 Gate issuance on an `active` account in both `/device/authorize` and `/device/token`; a non-active account yields no key with a clear status. `/device/token` re-checks status at exchange time too (the account could be disabled in the gap between approval and exchange); the code is still spent either way.
- [x] 2.6 Add cleanup of expired authorization codes (alarm or on-write pruning). — on-write pruning: `DELETE FROM device_auth WHERE expires_at < now` runs before every insert and every redeem.
- [x] 2.7 Unit-test the endpoints: happy path, expired code, replayed code, `state` mismatch, non-active account. — same D1-mock-harness gap as 1.4: manually verified end-to-end against `wrangler dev` (happy path, replay rejection, conflict detection, approve-during-conflict 409, replace targets the correct machine + revokes the prior key, separate creates a distinct `machine_id` and leaves the original untouched, open-redirect `cb` guard, missing/invalid code, non-active account); automated coverage lands in the QA e2e (6.1).
